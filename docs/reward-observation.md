# rewardの手動観測

`tools/reward-observer.js` は操作を行わず、手動のスクロール・追加読み込み中の画面構造の変化を記録します。
ログは同じタブのsessionStorageに蓄積します。ページを再読み込みしても保持されますが、タブを閉じる前にエクスポートしてください。

## 準備

1. rewardタブでChrome DevToolsを開き、Sources → Snippets → New snippetを選びます。
2. `tools/reward-observer.js` の内容を貼り付け、`reward-observer` として保存します。
3. Snippetを実行します（Ctrl+Enter）。Consoleに「第1回」と表示されます。

## 10回以上の観測

毎回、ページを再読み込みした直後にSnippetを再実行してください。自動実行はしません。

1. コンテンツタブを選択し、下端までスクロールします。
2. 追加読み込みボタンがあれば押し、項目が増えるまで待ちます。これを繰り返します。
3. 最後にボタンがなくなったら、そのまま20秒ほど待ちます。100貢未満で打ち切る場合は、それが全件読み込み完了とは異なることを記録してください。
4. 気付いたことがあればConsoleで `kokenRewardObserver.mark("ボタンが消えたまま20秒。画面のスピナーは回っている")` のように印を付けます。
5. `kokenRewardObserver.stop()` でその回を終了し、次の再読み込みへ進みます。

最低10回実施します。最初の再読み込みも1回に数えます。自然な遅延・失敗が発生しなければ「未再現」としてください。
通常の手動操作と、登録済み自動読み込みブックマークレットの実行は別の回として記録し、markで区別すると比較できます。
ブックマークレットによるHTML保存のダイアログが出たら、記録は一時的に止まるため閉じてください。

最後にConsoleで `kokenRewardObserver.export()` を実行し、ダウンロードされた `koken-reward-observations.json` をこのチャットへ渡してください。
各回終了時にもエクスポートできます。最後のJSONに同じタブの全回が入ります。

## ログの内容と限界

- クリック、DOM構造・属性の変化、100ms間隔での表示状態の変化を経過時間付きで記録します。
- ページの高さ、スクロール位置、項目数、追加ボタンの無効状態、読み込み・エラー候補のクラス／ARIA属性／CSSアニメーションを記録します。
- HTML全体、作品タイトル・URL、Cookie、通信本文、認証情報は取得しません。ボタンのラベル、クラス名、手動のメモは記録されます。
- 画面内の候補構造から調べるため、未知の読み込み表示を必ず捕捉できるとは限りません。見えた表示をmarkで補足してください。
- 画面から通信の成功・失敗を確定できるとは限りません。offlineイベントも通信失敗の確定情報ではありません。
- 1回10分または5,000イベントで停止します。上限到達はログに記録します。短時間の変化やバックグラウンドタブでの変化を取り逃す可能性があります。
- 記録処理・DevTools自体がタイミングに影響する可能性があります。今回のログだけで遅延の頻度や上限を保証することはできません。
- Consoleに保存失敗の警告が出たら、再読み込み前にexportしてください。その回はメモリにのみ残っている可能性があります。

調べる重点は「クリック後、何がいつ消え、何が現れるか」「項目追加から次のボタン表示までの空白」「完了と失敗で構造が違うか」です。
